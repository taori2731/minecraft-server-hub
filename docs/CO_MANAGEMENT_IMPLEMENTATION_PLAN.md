## PostgreSQL・Cloudflare追補（2026-09-08）

- 中継Storeを非同期契約にし、`PostgresRelayStore`、番号付きマイグレーション、チェックサム検証、接続プール、共有PostgreSQLレート制限を追加した。
- 設定操作の完了結果と運用監査メタデータを同じトランザクションで保存し、監査の90日保持・各ホスト/サーバー最新10,000件保持とレート制限整理を、アプリケーション権限と分離した保守コマンドへ切り出した。リレー監査は変更キーと結果だけで、変更前後の値を含む正式な監査はホストSQLiteが保持する。
- ホスト・サーバー・参加者・操作は複合キーで分離し、招待引換は行ロックとトランザクションで1回だけ成功させる。
- CSRFはハッシュだけを保存し、参加照合コードと操作結果は鍵ID付きAES-256-GCM暗号文で保存する。先頭鍵で暗号化し、過去鍵を復号専用として残せる。
- PostgreSQLまたは共有レート制限が利用不能な場合、HTTPは503、認証済みホスト処理はWebSocket 1013で停止し、Memory Storeへフォールバックしない。

- PGlite隔離DBで、同時招待引換、資格情報上書き拒否、複合操作ID、暗号文保存、共有レート制限、DB障害時停止を自動試験した。これは管理PostgreSQLやネットワーク障害の実機証明ではない。

- Rustlsの暗号プロバイダーをアプリ起動時とHTTP/WSS接続前に明示選択し、公開ステージングのRust統合試験でホスト登録、`host.ready`、招待引換、参加申請、設定取得を確認した。

## 1. 初版の完成条件

ホストが指定した1台のゲームサーバーに対して、招待・承認された友達がPC/スマートフォンのブラウザで状態と許可された設定を確認し、編集者は停止中に設定を保存できる。ホストは参加者と権限を確認・取消しできる。

ゲーム参加用招待と管理用招待は別にする。ホストPCとアプリが起動中で、共同管理を有効にしている間だけ利用できる。クラウドからPCを起動しない。

初版に含めるもの:
- Minecraft Java・Bedrock・Palworldの読み取り専用概要、許可設定の閲覧と変更。
- サーバー単位の閲覧者・編集者、期限付き招待、ホストの初回承認、失効。
- 設定変更差分、競合検出、設定退避と失敗時の復旧、操作履歴。
- 接続中・ホスト不在・権限失効・未対応バージョンの表示。

初版に含めないもの:
- 遠隔の起動・停止・再起動、任意コンソール、ファイル閲覧・編集・アップロード。
- ワールド削除・復元、Mod導入、Javaや実行引数変更、公開ポートやトンネル操作。
- 管理・参加パスワードの閲覧変更、他メンバーの招待、ホスト権限の委譲。
- インターネット切断中の操作予約、PCの常駐サービス化、課金、複数ホストの一括管理。

## 2. 接続構成

友達のブラウザ → HTTPS → 専用Web UIと中継API → 既存のWSS接続 → ホストのRust処理 → ゲーム別の設定保存処理。

- ホスト側が中継へ外向きのWSS接続を作る。PC側の管理用待受ポートやルーター設定は追加しない。
- ゲーム用playit.gg/UPnPの経路とは完全に別にする。Palworld REST管理ポートをブラウザや中継へ渡さない。
- ブラウザは同一オリジンのHTTPS APIを使い、初版の状態更新は5秒間隔の取得でよい。ブラウザ側WSSは初版に不要。
- 中継とブラウザUIは独立した配布物。既存の紹介サイトwebsite/は変更しない。
- ブラウザUIはReact/TypeScript。中継はNode.js/TypeScript + Fastify + ws + PostgreSQLを実装候補とし、Lunaが着手時に公式仕様・互換性を確認してバージョン固定する。
- 中継はまず単一インスタンス。TLS終端・永続DB・レート制限・運用ログを備える。Redisや複数リージョンは初版に不要。
- ホスティング会社、実ドメイン、月額上限は未決定。ローカル実装とテストは進められるが、本番構築・契約はこの決定後。

この方式は中継を信頼するTLS方式であり、エンドツーエンド暗号化とは呼ばない。中継運営者は許可された設定内容を処理し得る。利用開始時に通信先・送信項目・依存サービスを説明する。

## 3. 本人確認と権限

- 初版はアカウント作成を必須にしない。ブラウザのセッションを参加者として扱う。表示名は本人証明ではない。
- ホスト端末は初回登録で端末用資格情報を取得し、Windows資格情報マネージャーへ保存する。中継には検証用ハッシュのみ保存する。登録APIを制限し、ホストIDの推測だけでは接続や乗っ取りができないようにする。
- ホストが対象サーバーと閲覧/編集を選択し、招待を発行。暗号学的乱数32バイト以上、有効10分、1回使用、DBにはハッシュ保存。
- 招待秘密値はURLフラグメントに置く。ブラウザは読み取ったらURLから除去し、HTTPS POSTで引き換える。アクセスログ、解析サービス、Refererへ出さない。
- 引き換えは原子的に1回だけ成功する。成功してもまだ管理権限は与えない。
- ホスト画面に参加申請と照合コードを表示。友達にも同じコードを表示し、ホストが確認・承認した時だけ権限を有効化する。リンクを盗んだ人が先に引き換えた場合は取消して再発行する。
- セッションCookieはSecure/HttpOnly/SameSite=Strict。管理トークンをlocalStorageへ保存しない。
- 初期値: 無操作30分、絶対期限12時間。ホストの接続再開・アプリ再起動時は以前の共同管理セッションを再承認対象にする。期限はサーバー側で強制する。
- ホストのローカルDBが対象サーバー・参加者・権限・失効の最終権威。中継の認証済み参加者情報と照合し、すべての操作で再検証する。
- ホスト端末の取消しはその場でローカルに確定してから中継へ通知。接続済みでも次の操作は拒否。未実行の操作も取消し、実行開始済みの保存は安全に完了/復旧して記録する。
- 中継のCookieセッション、ホスト接続、承認済み参加者を紐付ける。ブラウザが送ったuserId/role/hostIdを認証情報として信頼しない。

## 4. 公開する情報と設定

ServerProfileをそのまま返さず、共同管理専用DTOを作る。返すのはサーバー表示名、ゲーム種別、状態、人数、取得時刻、設定リビジョン、許可された設定と編集可能条件のみ。
PCパス、IP、資格情報、接続文字列、ゲームログ全文、プレイヤーID、非共有サーバー一覧は返さない。

初版の編集候補を以下に限定し、ゲーム別の実対応が確認できた項目だけcapabilitiesで公開する。非対応項目を黙って成功扱いにしない。

| ゲーム | 許可する設定 |
|---|---|
| Minecraft Java | difficulty、defaultGameMode、maxPlayers、pvp、allowFlight、forceGameMode、spawnProtection、viewDistance、simulationDistance |
| Minecraft Bedrock | difficulty、defaultGameMode、maxPlayers、viewDistance。既存保存処理の対応を検証した項目のみ |
| Palworld | serverDescription、maxPlayers、expRate、collectionDropRate、palCaptureRate、dayTimeSpeedRate、nightTimeSpeedRate、palEggDefaultHatchingTime、deathPenalty、invaderEnemiesEnabled、fastTravelEnabled、baseCampMaxNumInGuild、baseCampWorkerMaxNum |

onlineMode、whitelist、allowCommands、ポート、メモリ、実行引数、パスワード、REST設定、ゲームサーバーの管理者設定はホスト専用。数値の範囲・enum・文字数は既存のゲーム別検証を再利用し、外側でも未知フィールドを拒否する。

Windows通知と無人時停止の設定は初版の共同管理対象外。ホストのPC運用方針としてローカルで管理する。

## 5. 保存・競合・通信断

1. ホストから設定とrevisionを取得し、ブラウザで編集する。
2. 変更差分と「次回起動から反映」を表示。送信時はrequestId、expectedRevision、許可フィールドの差分だけを送る。
3. Rust側で参加権限、期限、サーバーID、ゲーム種別、フィールド、型、値を検証する。
4. ローカル操作と共通のサーバー単位排他を取得。排他内で停止状態とrevisionを再検証する。起動中・停止処理中・異常終了状態は初版の編集を拒否する。
5. 対象設定を退避。ローカルの未公開設定を保持したまま差分を適用し、既存ゲーム別処理で保存する。成功時にrevision更新と監査結果を確定する。
6. 失敗時は退避から復旧する。復旧に失敗したら変更を成功扱いにせず、そのサーバーへの追加変更を止め、ホストに復旧が必要と通知する。

- UIでボタンを無効にするだけでは不可。既存のTauri更新・起動・削除・復元も同じ排他/リビジョンに参加させる。
- 外部エディターによる変更は、対象設定ファイルの指紋を読み直して検知し、上書きを拒否する。すべての外部プロセスを完全に排他できるとは主張しない。
- 旧revisionは409 Conflict。差分を再取得して利用者に選び直してもらう。最後の保存で無条件に上書きしない。
- 1台につき変更処理は1つ。切断中の操作は即時失敗とし、中継で後日実行するキューを作らない。
- requestIdと送信者・対象・内容のハッシュ・実行状態をホストへ永続化。同じIDで別内容は拒否する。
- 保存成功後に応答が消えた場合は同じIDの結果照会で確かめる。自動再実行しない。再起動時に実行途中なら退避/ファイル指紋と照合して復旧または要確認にする。「厳密に1回実行」を根拠なく保証しない。
- revisionや監査記録を含むDBと設定ファイルは単一トランザクションにはならない。退避と操作ジャーナルによる復旧を実装する。
- Palworldの設定退避はワールド全体のバックアップではない。既存のupdate_config/rollback_configを確認して利用し、復旧失敗を握り潰さない。

## 6. 保存データとAPI境界

ホストSQLiteに共同管理の有効状態、サーバーごとの参加者権限と失効世代、revision、設定指紋、操作ジャーナル、監査履歴を追加する。資格情報はWindows資格情報マネージャー。
中継DBは端末、招待ハッシュ、セッションハッシュ、紐付けと有効期限を保存する。設定値・操作本文は通常ログやDBへ永続保存しない。切断時の状態キャッシュは破棄し、ブラウザでは最終取得値を古い情報として表示する。

APIの役割:
- 招待引換、セッション確認・終了。
- 共有サーバーの状態と編集capabilities取得。
- 許可設定の取得、差分保存、requestIdによる実行結果照会。
- 自分がアクセスできるサーバーの監査履歴取得。
- ホストの端末登録/接続、参加承認、取消しは別権限の経路。

ホスト接続プロトコルはバージョン付きの固定メッセージ種別とする。Tauriのコマンド名や任意URL・ファイルパスを中継が指定できる汎用実行口は作らない。
監査には参加者の内部ID/表示名、対象、時刻、許可項目の変更前後、結果、requestIdを残す。秘密値とログ全文は保存しない。ホスト側90日、上限10,000件を初期値とし、保存中処理のジャーナルを履歴整理で消さない。

認証・認可、CookieとCSRF対策、Origin検査、メッセージごとの検証、サイズ制限、接続/送信頻度制限、失効時の接続終了を必須とする。中継障害は共同管理だけを停止させ、ゲーム稼働とローカル管理を継続可能にする。

## 8. Lunaの実装順序と受け入れ条件

CM0: 既存処理の確認。src-tauri/src/lib.rsのupdate_server_settings、update_palworld_settings、起動/停止/削除/復元を調査し、共通サービスと排他の抽出範囲を報告。既存データや無関係な変更を保存する。

CM1: Rust共通サービス、権限/DTO、DB追加、排他、revision、監査、復旧を実装。まずネットワークなしでローカル操作の回帰を確認。

CM2: ローカル中継、ホストの外向き接続、招待/承認/失効。ブラウザに本物の管理APIを公開する前に認証・認可の否定テストを通す。

CM3: ブラウザUIとデスクトップ共同管理画面を接続。変更差分と競合・切断時の結果確認を実装。モックだけで完了扱いにしない。

CM4: 隔離したゲーム環境と別回線で実機確認。実ホスティング先と予算の決定後にステージングを作り、成功した構成だけを本番配布対象にする。

必要なテスト:
- 閲覧者の書込み、未承認/期限切れ/取消済み、別サーバーID、未知フィールド、型違い、任意コマンド・パス、Origin/CSRF不正を拒否。
- 同じ招待の同時引換は1件だけ成功。Cookieや端末IDだけの差替えでは承認対象を変更できない。
- ローカルと遠隔の同時保存、保存と起動の競合、外部ファイル変更、重複リクエスト、応答消失、再接続で上書き/二重実行しない。
- DB/設定ファイル書込み失敗・ディスク容量不足・復旧失敗時に結果と実ファイルが一致する。
- スマートフォンのブラウザから許可項目を変更し、ゲーム再起動後に実反映を確認。
