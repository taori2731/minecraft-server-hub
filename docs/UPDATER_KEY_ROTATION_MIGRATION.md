# Tauri updater鍵のローテーション移行手順

## この手順が必要な理由

このリポジトリには既に公開リリースがあり、旧公開鍵を埋め込んだインストール済み版から更新される可能性があります。公開鍵だけを先に差し替えると、旧版は新しい更新署名を検証できず、更新不能になります。

2026-09-10時点の確認事項:

- `minecraft-server-hub-releases` に一般向けの `v0.3.1`〜`v0.3.8` が存在します。
- この検証PCには Minecraft Server Hub `0.3.2` と Developer Tools `0.3.1` がインストールされています。
- メインアプリとDeveloper Toolsは現在同じupdater公開鍵を使用しています。

したがって、初回公開前の無利用者向けローテーションではなく、既存版を考慮した移行として実施します。

## 事前条件

1. SignPathの申請・GitHub App連携・手動承認ポリシーを完了します。
2. 新しいupdater秘密鍵を安全な環境で生成し、リポジトリへ保存しません。
3. メインアプリとDeveloper Toolsで鍵を共有し続けるか、製品ごとに分離するかを決めます。推奨は製品ごとの別鍵・別Secret・別フィードです。
4. 旧版利用者がいる間は、旧版から新鍵版へ移行する経路を用意します。

秘密鍵、秘密鍵パスワード、SignPath APIトークンはチャット・Issue・ログ・リポジトリへ貼り付けません。

## 推奨移行方式

旧秘密鍵が安全に使用できない、または表示・漏えいした可能性がある場合は、旧秘密鍵で新しいブートストラップ版へ署名しません。新公開鍵を埋め込んだインストーラーを、利用者が手動で入れる方式にします。

1. 新公開鍵をメインアプリの `src-tauri/updater-public.key` と `src-tauri/tauri.conf.json` に反映します。
2. Developer Toolsを分離する場合は、専用の新公開鍵を `developer-tools/src-tauri/updater-public.key` と設定へ反映します。
3. GitHub Actionsの署名Secretを新しい秘密鍵へ切り替えます。
4. 旧版を起動したままにせず、サーバー停止・バックアップ・設定保存を確認します。
5. SignPathでAuthenticode署名し、署名後の最終バイト列にTauri updater署名を付けた移行版を作ります。
6. 移行版をリリース用リポジトリへ公開する前に、管理者のWindows環境へ手動インストールします。
7. 新しい公開鍵で移行版から次の更新を検証できることを確認します。
8. その後だけ新鍵版の `latest.json` を公式フィードへ反映します。

## 手動移行の受入条件

- 移行版のWindows Authenticodeが `Valid`
- 移行版の隣接 `.sig` が新公開鍵で検証可能
- `latest.json` の署名と隣接 `.sig` が一致
- 旧版の設定、サーバー登録、バックアップ、権限が維持される
- Minecraft Server Hubの停止中更新が成功する
- Developer Toolsを別鍵へ分離した場合、その専用フィードも同じ条件を満たす
- アンインストール・再インストール後に設定方針どおり復元できる
- 外部変更、切断、途中終了、ゲーム再起動後の動作に回帰がない

## 旧版と旧フィードの扱い

- 旧リリース、旧 `.sig`、旧 `latest.json` は移行完了まで削除・上書きしません。
- 旧公開鍵を埋め込んだ版へ、新公開鍵で署名した更新を直接配布できるとはみなしません。
- 旧秘密鍵が漏えいした可能性がある場合、旧鍵で署名した成果物を信頼済みの本番更新として追加公開しません。
- 移行に失敗した場合は現在のアプリとフィードを維持し、手動インストール手順へ戻します。
