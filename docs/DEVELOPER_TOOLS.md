# Minecraft Server Hub Developer Tools

`developer-tools/`は、一般向けアプリとは製品名・アプリ識別子・実行ファイル・インストーラーを分離した、リリース／サプライチェーン／性能／品質証跡の検査用Windowsアプリです。Phase D31で署名付き更新の実機経路、9言語表示、完成版の保守境界を確定しました。以後は不具合修正と互換性更新を中心に保守します。

## ブラウザーで開発起動

```powershell
npm run dev:developer-tools
```

`http://127.0.0.1:1421/`を開くと、現在のワークスペースを再検査できます。

検査結果をレビュー用JSONへ保存する場合は、明示的な出力先を指定します。

```powershell
node scripts/developer-inspection.mjs . --output artifacts/developer-tools/d31-inspection.json
```

## Windowsアプリとして起動・ビルド

```powershell
npm run dev:developer-tools:desktop
npm run build:developer-tools:desktop
```

Windows版では任意のMinecraft Server Hubソースフォルダーを選び、ネイティブRust処理で検査できます。ライセンス審査台帳はアプリデータ内へ原子的に保存し、直近12回の検査概要、公開ポリシー、OSV結果の24時間キャッシュは端末内のWebViewストレージへ保存します。旧WebView台帳は最初の読込時に一度だけネイティブ台帳へ移行します。

- NSIS: `developer-tools/src-tauri/target/release/bundle/nsis/Minecraft Server Hub Developer Tools_0.3.1_x64-setup.exe`
- 製品識別子: `local.minecraft-server-hub.developer-tools`

## D31で完成させたDeveloper Tools専用更新

- 一般向けMinecraft Server Hubと分離した固定HTTPSフィードだけを確認
- 起動時は新しい版の確認だけを行い、自動ダウンロードと自動インストールを行わない
- 手動確認時にバージョン、公開日時、更新内容を表示
- 更新内容への明示チェックが入るまで更新ボタンを無効化
- Rust側でも明示同意、バージョン形式、確認時と適用時のバージョン一致を再検証
- Tauri Updaterによる署名検証を通過した成果物だけを適用
- 確認、ダウンロード、署名検証、適用に失敗した場合は現在のアプリを維持
- 更新フィードへワークスペース、検査履歴、ライセンス台帳を送信しない
- 日本語を含む9言語で更新状態、安全境界、エラーを表示
- 通常の開発ビルドと、秘密鍵を明示した署名付き公開ビルドを分離

公開手順と初回導入の境界は`docs/DEVELOPER_TOOLS_UPDATE_RELEASE.md`を参照してください。

- コマンドパレットの20項目の表示文言と安全境界を9言語で表示し、初期バンドルから遅延分離

## 品質証跡を生成する

品質センターを開く、ワークスペースを選ぶ、再検査するだけではテストやビルドを実行しません。開発者がターミナルで次を明示的に実行した場合だけ、証跡を更新します。

```powershell
npm run quality:verify
```

結果は`artifacts/developer-tools/quality-evidence.json`へ原子的に保存し、カバレッジ集計は`coverage/quality/coverage-summary.json`から取り込みます。実行中に対象ソースが変わった場合、または途中の段階が失敗した場合も証跡を残しますが、公開前チェックでは合格扱いにしません。

7段階は次の固定順です。

1. 一般向けアプリのTypeScript型検査
2. Developer ToolsのTypeScript型検査
3. Vitest全体テストとV8カバレッジ
4. Node版読み取り専用検査器テスト
5. Developer Tools Rustの`cargo fmt --check`
6. Developer Tools Rustの`cargo test --locked`
7. 一般向けアプリのレンダリングUIスモーク

一般向けアプリの本番ビルドはD5のバンドル証跡、Developer Tools自身のビルドはD21承認とD22ハンドオフが参照するD20証跡を読み込む工程と循環するため、この7段階には含めていません。公開候補では品質証跡に加えて、各アプリの本番ビルドを別途実行してください。

## 安全境界

- 署名用秘密鍵を読み込みません。
- ビルド、署名、GitHub公開、アップロード、削除は実行しません。レポート出力だけは保存ダイアログで選んだファイルへ書き込みます。
- 署名検証は設定済み公開鍵だけを読み込み、署名用秘密鍵にはアクセスしません。公開工程では独立した証跡として`docs/APP_UPDATE_RELEASE.md`記載の無視指定Rustテストも実行します。
- 公式フィードが一時的に利用できない場合は「要確認」とし、ローカル成果物の破損とは断定しません。
- npmやRustの脆弱性情報を無断送信しません。OSV照会では固定された`https://api.osv.dev/v1/querybatch`だけを使い、パス、取得元、ライセンス、ロックファイルを送りません。照会ボタンは送信項目を表示したうえで同意チェックを入れるまで有効になりません。
- OSV結果は照会対象のSHA-256ダイジェストをキーに24時間だけ保存し、依存関係が変わると再利用しません。
- SBOM／CSV／ライセンス審査台帳／Windows x64証跡／第三者通知の出力は16MiB以下の認識済み形式だけを受け付け、既存の親フォルダーを持つ絶対パスへ保存します。監査JSONは固定ドキュメント種別、スキーマ、64桁の依存ダイジェスト、論理パス、64桁SHA-256、固定された公式ライセンス補完情報だけを受け付けます。
- ライセンス分類は法的判断ではありません。不明・相互ライセンスを公開前レビューへ回すためのローカル棚卸しです。
- 審査台帳は法的助言ではありません。審査者と根拠を伴う判断の追跡を目的とし、依存メタデータが一致しない古い記録や有効期限を過ぎた記録は公開前チェックへ反映しません。
- ネイティブ審査台帳は依存ダイジェストごとに分離し、4MiB・4,000イベントを上限とします。台帳本体・親フォルダー・一時ファイル・バックアップがシンボリックリンクの場合は拒否します。連鎖検証に失敗した台帳から判断を復元せず、すべて未審査として扱います。
- `.mshlicense`はユーザーが選んだ既存フォルダー内の絶対パスだけを受け付け、拡張子、4MiB上限、依存ダイジェスト、時刻順序、連番、全イベントハッシュ連鎖を検証します。これは破損・意図しない変更の検出であり、第三者の署名による真正性証明ではありません。
- 復元は自動マージを行いません。現在台帳を延長する同一イベント列だけを受け入れ、プレビュー後にファイルまたは現在台帳が変わった場合は停止します。内部リカバリーフォルダー内のファイルを復元元として直接選ぶことも拒否します。
- 復旧履歴センターは内部ファイルを変更・削除・直接復元しません。通常ファイル、認識済みファイル名、4MiB以下、依存ダイジェスト一致、時刻・連番・イベントハッシュ連鎖一致を満たす項目だけを検証済みとし、出力直前にもSHA-256と最新ハッシュを再検証します。
- ライセンス根拠収集はネットワークへ接続せず、パッケージを取得・展開・変更しません。既存の`node_modules`、Cargoレジストリソース、Cargoキャッシュ、Cargo Gitチェックアウトだけを読みます。Gitチェックアウトは40桁のロック済みコミットと一致するものだけを受け入れ、探索深度・件数・manifestサイズを制限します。
- MPL補完検査も実行時ネットワークへ接続しません。Mozilla公式のMPL 2.0全文をビルド時に同梱し、固定SHA-256が一致する場合だけ、最大8KiBまで読み取ったパッケージソースの標準MPLヘッダーと結び付けます。
- npm適用性はロックファイルの明示的な`os`／`cpu`条件だけで判定します。Cargo適用性は既存ロックを固定し、ネットワークを無効にした`cargo metadata`のWindows x64グラフだけで判定します。コマンド失敗時は、パッケージ名などで推測せず未判定のままレビューへ回します。
- 根拠ファイルはトップレベルまたは`LICENSES/`直下だけを対象にし、1ファイル2MiB、1パッケージ16ファイルを上限とします。UIへはファイル名、分類、サイズ、SHA-256だけを返し、本文とキャッシュの絶対パスは返しません。
- バンドル分析はビルドコマンドを起動しません。既存の`dist/bundle-report.json`だけを最大4MiBまで読み、ソースより古い場合は公開証跡として扱いません。
- ローカル基準はWebViewのバージョン付きキーへ、サイズ・チャンク数・保存日時だけを保存します。ソースパスやファイル内容は保存しません。
- 品質センターは検証コマンドを自動実行しません。既存の証跡を最大8MiBまで読み、固定されたソース対象との一致を確認するだけです。
- ソース指紋は認識済みの設定・スクリプト・TypeScript／Rustソースだけを対象にし、`node_modules`、`target`、`dist`、`coverage`、`artifacts`を除外します。単一ファイル8MiB、合計128MiB、2万ファイルを上限とします。
- 品質履歴はWebViewのバージョン付きキーへ最大8件の集計値だけを保存し、コマンド、失敗ログ、ファイルパス、ソース内容は保存しません。
- 承認画面はビルド、署名、アップロード、公開を行いません。承認者と理由はDeveloper Toolsのアプリデータ内だけに保存し、候補のワークスペースには書き込みません。承認は公開実行ではなく、その時点の正確な証跡に対するローカル監査判断です。
- `.mshhandoff`は公開担当へ渡す検証可能な承認証跡であり、公開命令ではありません。承認者名・理由は外部ファイルへ含めず、保存先は既存フォルダー内の新規`.mshhandoff`だけを受け入れ、20MiBを上限とします。
